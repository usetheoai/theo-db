# M110 — in-DB graph extraction: parity + throughput

**Date:** 2026-07-16 · **Milestone:** M110 (native graph pillar Phase 3) · **Raw data:** [`m110-extraction.json`](./m110-extraction.json)
**Hardware:** DigitalOcean DO-Regular, 4 vCPU @ 2.0GHz · pgrx 0.19 / PostgreSQL 17.

## The gate: cross-language parity (recall non-regression by construction)

theo-rag's own graph-quality baseline **IS** the heuristic extractor (`graph-extractor.ts`). So proving the in-DB
`ai.extract_entities`/`ai.extract_graph` is **byte-identical** to theo-rag's extractor — plus that the traversal
returns the same reachable set (M108/M109 set-hash) — proves downstream retrieval recall is **non-regressed by
construction**, without a separate QA eval run (blueprint ADR-2).

**Parity coverage = 100%** — the entity set `(name, normalized_name, mention_count)` and the co-occurrence edge
set `(src_norm, dst_norm, weight)` are asserted byte-identical to golden values generated by running theo-rag's
real compiled `dist/domain/extraction/graph-extractor.js` on the fixture chunks (tests
`m110_extract_entities_parity`, `m110_extract_graph_parity`, `m110_extract_stopword_and_multiword`). Not
hand-traced — the golden is the actual theo-rag output.

## Throughput (heuristic path, 500 chunks, mean of 3 runs)

| Metric | Value |
|---|---|
| `ai.extract_graph` extraction | **1537 chunks/sec** (325 ms / 500 chunks) |
| `theodb.graph_upsert` (extract + idempotent node/edge upsert) | 108.7 chunks/sec |
| total edges extracted | 5000 |

Extraction is pure in-backend Rust (no I/O, no LLM) → ~1.5k chunks/sec. The upsert path is slower because it
does 2 parameterized round-trips per entity/edge (`ON CONFLICT` node + edge upserts over SPI) — still ~109
chunks/sec, ingest-adequate; batching the upserts is a documented future optimization.

## E2E integration proof (the payoff)

`m110_e2e_extract_to_expand`: `theodb.graph_upsert` a 3-chunk corpus (Alice-Bob-Carol-Dave chain) →
`theodb.graph_build('theodb.graph_edges','src_id','dst_id')` → `theodb.graph_expand` from Alice's node id
returns {Alice,Bob} at 1 hop and all 4 at 3 hops. theo-rag's graph strategy sheds `extraction/` + `graph-store/`
+ the recursive CTE for 3 SQL calls: `graph_upsert` (ingest) → `graph_build` (once) → `graph_expand` (retrieve).

## Honest scope & caveats

- **Heuristic recall < LLM** (~2× on MINE, blueprint Corner 4). The gate is non-regression vs theo-rag's
  heuristic baseline (itself heuristic → parity by construction), NOT an absolute-quality claim. The `use_llm`
  path is wired (reuses `chat::chat` with a GraphRAG delimited prompt, parser tested, fail-soft to heuristic on
  unparseable reply) — its absolute multi-hop quality gain is a separate measured study (blueprint ADR-2), not
  required to ship the heuristic surface.
- Unicode parity holds for English text (Rust `char::is_alphanumeric`/`is_uppercase` ≈ JS `\p{L}\p{N}`/`\p{Lu}`);
  the parity test catches any divergence on the fixtures.
- `graph_build` scopes over the whole edge relation — per-workspace CSR needs a filtered view (follow-on); the
  E2E test uses a single workspace. Tenant isolation of the tables themselves is proven (`m110_upsert_tenant_isolation`).
