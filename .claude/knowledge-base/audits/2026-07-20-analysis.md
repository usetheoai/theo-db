## A1 / A5 — Performance & scalability (measured)

- **Recall:** own-code parity with pgvector HNSW achieved (M45 parity, M60/M69/M70). Not superior to ScaNN — the
  ADR-0002 QPS-superiority mandate is **structurally unachievable** by a permissive PG extension (AH-LUT +
  MVCC/WAL tax), MEASURED and recorded (ADR-0035/0036), and the North Star was formally repositioned (ADR-0033):
  "paridade recall + memória billion-scale + AI-native/HTAP/aberto" — never "faster than AlloyDB on vectors."
- **Multi-client:** at 1M×128d / 8 concurrent clients, theodb_hnsw **beats** pgvector +11% QPS at matched recall
  (M72) — the regime that actually matters for a served DB.
- **Memory / billion-scale:** SQ8 3.52× smaller (M83–89); the honest limit is `1× idx.vectors` (100M does not fit
  → tuplesort streaming is the tracked follow-up, ADR-0038/0039). This is the axis where the project is strongest.
- **Columnar/HTAP:** 6–13× byte-identical filtered/grouped aggregates; ~1300× min/max fast-path (M114–121). A
  differentiated, measured HTAP bet (lakehouse/DuckDB-style, not AlloyDB's in-memory columnar — D2).

## A3 / A2 — Architecture & complexity (static)

- Layering is coherent: `am/` (PostgreSQL index/table-AM contract) → `ann/` (HNSW/IVF/SymphonyQG algorithms) →
  `vec/` (SIMD kernels) → `columnar/`, `graph_rag`, `vectorizer`, `hybrid`, `embed`. No circular-dependency
  evidence surfaced; composition root is the extension entry.
- **Complexity risk:** 32,138 LoC; **19 files > 500 LoC**; `am/hnsw_page.rs` at **3,456 LoC** is a hot-path
  god-file — the highest-churn, highest-risk module (it is where M35/M118/M122-adjacent work concentrates). Not a
  trajectory blocker, but the top maintainability risk.

## A4 — Memory & safety (static)

- **357 `unsafe` blocks across 30 files** — expected and unavoidable for a pgrx extension (every SPI/FFI/page/WAL
  call crosses the C boundary). The mitigation is real: the council-rust-pgrx review lens is applied per slice
  (e.g., M122 verified longjmp/AssertUnwindSafe/owned-values), and 230 Rust test fns + crash harnesses back it.
  The risk is concentration in the big AM files, not the count itself.

## A6 — Reference comparison

- **vs pgvector** (`references/pgvector`): recall parity (own code) + a measured multi-client QPS win + own
  permissive vector type (no pgvector dependency in the distribution). Superior on openness/portability.
- **vs pgvectorscale/DiskANN** (`references/pgvectorscale`): studied, not forked (AGPL — study-only); own SBQ/AQ
  quantization instead.
- **vs ScaNN/AlloyDB:** honest QPS gap at high recall (paradigm-level), repositioned; TheoDB wins today on
  openness, cost, portability, model-independence.
