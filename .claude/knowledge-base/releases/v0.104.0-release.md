## Release notes

### Added — Numeric-output integer aggregates (`sum(int8)` + `avg(int2/4/8)`) byte-identical

Extends the M100/M114 columnar aggregate CustomScan to admit the two integer aggregates M114 declined because their
output is PG `numeric`. DataFusion computes `sum(cast AS Decimal128(38,0))` (i128-exact) + `count`; pgrx `AnyNumeric`
builds the PG numeric — `avg` delegates division to PG's own `numeric_div` (data-dependent scale).

**Measured (1M rows, c-8 droplet — `docs/benchmarks/numeric-output-aggregates-verdict.md`): GOAL MET** — every shape
byte-identical to the heap (as TEXT) with the CustomScan engaged. `sum(int8)` proven over a sum exceeding i64 max
(1e19, the Decimal128/i128 path); `avg(int2/4/8)` reproduces PG's shrinking avg scale (16→12→8 sig-digits); empty group
→ SQL NULL. Scalar + GROUP BY; 7.14–10.10× vs native.

Scope: integer input only — `sum/avg(numeric)` column input deferred (Arrow Decimal128 column decode).

## Validation methodology note

`cargo pgrx test` is inexecutable on the build droplet (standalone test-runner cannot resolve PG server symbols —
pre-existing pgrx harness/environment limitation, affects all tests identically, at crate-link stage before any test
runs). The `#[pg_test]` is committed as an executable RED-shape gate + documentation; the acceptance evidence is the
in-PG A/B integration benchmark (1M rows, real backend, EXPLAIN-verified CustomScan) — the project's established
validation path (M114/M115 used the same).
