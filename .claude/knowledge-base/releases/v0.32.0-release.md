## Release notes

### Added
- M35 — `theodb_hnsw` page-native structured scan: O(N) whole-blob deserialize → O(ef·M) on-demand traversal
  (meta + element tuples + neighbor tuples, à la pgvector). Adds `theodb_hnsw.ef_search` GUC (default 64). At 1M
  (SIFT1M), matched-recall point (ef_search=100, recall 0.979 ≥ blob 0.964): ~100 QPS = **~61× the O(N) blob**
  (up to ~194× at recall 0.93); pages-read flat-in-N (O(ef·M)). Build ~17.5 min (single-thread). INSERT/DELETE/
  VACUUM intact. Evidence: `docs/benchmarks/m35-hnsw-structured-scan.{md,json}`.

### Changed
- BREAKING (pre-1.0): `theodb_hnsw` on-disk format changed (blob → structured). Legacy blobs still read via the
  O(N) path; REINDEX for the structured speedup. No data loss. `theodb_ivfflat` unaffected.

## Outcome

Both QPS levers M32 identified are now closed — theodb_ivfflat (M34) and theodb_hnsw (M35) are partial-read at 1M.
The O(N)→O(ef·M) transformation makes theodb_hnsw practical at scale (~61× vs its prior blob at preserved recall).
