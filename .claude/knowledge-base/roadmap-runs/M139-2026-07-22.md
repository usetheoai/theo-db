# Milestone M139 — SPIKE: Directory do Tantivy sobre block storage do Postgres

## Outcome

VEREDITO **GO**, todos os 4 gates MEDIDOS em PG18 real (atrás da feature `spike-lexical`, fora do build shipado):
gate 1 index+search sem fs (5 testes), gate 2 MVCC cross-session, gate 3 crash-real+WAL replay, gate 4 custo
favorável (índice 2,8× menor que pg_textsearch, latência competitiva). Achado central: o Tantivy chama o
Directory de múltiplas threads → arquitetura **buffer-then-flush** (buffer pgrx-free em memória; flush ao heap
`bytea` na main thread → MVCC+WAL+TOAST do PG de graça, Rule 9), sem código de página/WAL custom nem fork
(Tantivy MIT stock resolveu). Review pgrx (`council-rust-pgrx`) validou o claim de thread-safety sem furo.
ADR 0051 (Aceito/GO). A engine lexical própria é VIÁVEL → M140 (produção: cache, merge, VACUUM; residuais em
#153). O valor: descobrir viabilidade + arquitetura correta em uma sessão, medido, não em trimestres.
