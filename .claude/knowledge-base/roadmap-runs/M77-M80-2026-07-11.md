# Milestones M77+M78+M79+M80 — IVF-AQ+batched-AH no AM theodb_ivfflat (entrega em lote)

## Outcome

A capacidade que o M75 spike provou (~5-7× QPS), agora **em produção no AM PostgreSQL**, numa mudança isolada e
testada. `CREATE INDEX ... USING theodb_ivfflat WITH (pq_subspaces=M)` → layout **v4** (`page.rs::write_ivf_aq`):
códigos AVQ 4-bit em block32 transposto por inverted list + f32 (rerank) + codebook persistido. ambuild ramifica
(`build.rs`: pq_subspaces>0 → treina AVQ + `pack_block32_codes` → write_ivf_aq). scan (`scan.rs::scan_ivf_aq`):
probe → `ah_score_block` batched (FastScan pshufb) → rerank f32 exato — O(probes) reads.

**PROVADO em pgrx real:** `ambuild_ivf_pq_subspaces_v4_scans_high_recall` (recall@10 ≥ 0.8 vs seqscan exato) +
**235 pg_tests GREEN, ZERO regressão** (o path v3 f32 intocado, byte-idêntico). Fecha o mecanismo de M77 (layout),
M78 (AVQ encode no build), M79 (scan batched-AH), M80 (rerank f32).

**Honesto (Regra 3):** o benchmark recall×QPS a **SIFT1M** é o **M82** (exige otimizar o `AqQuantizer::train`
super-linear, que bloqueou o 1M no M75). O lifecycle **aminsert/VACUUM do índice v4** é o **M81** (hoje o v4 é
read-mostly; aminsert/VACUUM em v4 = follow-up). `over_fetch` GUC serve de rerank pool. Release v0.69.0.
