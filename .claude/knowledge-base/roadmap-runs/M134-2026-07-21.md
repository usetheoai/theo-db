# Milestone M134 — Fix #117: blind SSRF via a caller-settable `theodb.llm_endpoint`

## Outcome

Closed. The endpoint and key GUCs are operator-only (`42501` for anyone else), and a fail-closed egress guard at
the single outbound HTTP call refuses loopback/RFC1918/link-local/NAT64/6to4/CGNAT/multicast targets with a typed
`22023`, covering embed, chat and rerank at once. A superuser-only allowlist keeps real on-prem endpoints
reachable and is proven scoped rather than a global off-switch.

The review earned its keep: the first cut was **bypassable** — the guard parsed URLs per RFC while `minreq` does
not implement userinfo and silently falls back to port 80, so `http://169.254.169.254:x@api.openai.com/v1` dialed
the metadata service, and one of my own tests had blessed the wrong model. Fixed by mirroring the client's parser;
an independent second security pass then found zero mismatches across 47 adversarial URL shapes. A cross-validation
pass separately found five acceptance criteria whose *proof* had drifted from the plan (SQLSTATE, allowlist
scoping, multi-A, latency, REVOKE grep) plus a silent reversal of the plan's `*_model` decision — all closed with
measurements, the reversal reverted.

Carried openly into the release: the DNS-rebinding TOCTOU (resolve-and-check, not resolve-then-connect — `minreq`
exposes no connector hook), and the fact that the three `#[pg_test]` cases have never executed because
`cargo pgrx test` does not link on this droplet. Both are recorded as unmet/limited rather than reworded to fit.
