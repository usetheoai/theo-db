# Milestone M158 — Late materialization (columnar scan perf)

## Outcome

Late-materialization top-k CustomScan for `SELECT <cols> ORDER BY key LIMIT k` over columnar tables:
decode the projection to one Arrow batch, DataFusion filter→sort→limit(k), materialize PG tuples ONLY for the
k survivors (skips M148 form_row/palloc for N-k rows). Measured **1.60× median** (2M×30 SELECT* ORDER BY LIMIT 10),
byte-identical + order-identical A/B (diverged=0). GUC `theodb.enable_columnar_late_mat` default OFF (honest O(N)
Arrow-batch memory vs O(k) native heapsort trade-off). Councils fixed a text-collation HIGH (byte-order C/POSIX only)
and a benchmark-timer inflation (re-measured clean 1.60× vs 1.64× ANALYZE-inflated). Released v0.149.0 (PR #201).
