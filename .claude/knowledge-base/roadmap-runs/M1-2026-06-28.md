# Milestone M1 — Core + empacotamento

## Objective (from ROADMAP.md)

Distribuição PostgreSQL-compatível completa em imagem container, com extensões pré-instaladas e a
suíte de compatibilidade do upstream passando.

## Definition of done (from ROADMAP.md)

- **DoD-1:** suíte de regressão do PostgreSQL upstream passa 100% na distribuição. ✅
- **DoD-2:** extensões do MVP pré-instaladas e habilitáveis via `CREATE EXTENSION`. ✅
- **DoD-3:** due-diligence de licença — zero AGPL no pacote. ✅

## Outcome

M1 entregue end-to-end com evidência verificada ao vivo (review READY_TO_MERGE, 3/3 DoDs):
suíte de regressão PG17.10 upstream **225/225** na distribuição (runner throwaway `FROM theo-db:dev`,
engine assertado = PGDG 17.10); 4 extensões MVP habilitáveis; **zero AGPL** via gate reprodutível
`packaging/license-sweep.sh` (apt + 293 crates Rust). Release **v0.5.0** (PR #6, merge `1e4151d`, tag
anotada `v0.5.0`, GitHub release publicado).

## Nota de rastreabilidade — inversão de ordem de roadmap (MEDIUM-1 do review)

M1 (Core) é dependência conceitual de M2/M3/M4, mas foi **formalizado por último** (M2→M3→M4→M1).
Isto é uma inversão de ordem de roadmap, **não** um defeito: M2/M3/M4 já dependiam de fato da mesma
imagem `theo-db:dev` (PGDG 17 + extensões) que M1 agora documenta e prova. O release de M1 **legitima
retroativamente** a base sobre a qual M2/M3/M4 já foram entregues e released (v0.2.0/v0.3.0/v0.4.0).
Honestidade extrema (Regra 3): a sequência de entrega não seguiu a numeração, e isso fica registrado aqui.
