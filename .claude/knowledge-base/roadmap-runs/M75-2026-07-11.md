# Milestone M75 — Fase 0 pg_scann: spike D3 de viabilidade IVF-AQ+AH (o GATE)

## Outcome

CYCLE: DISCOVER (blueprint SHIPPABLE_WITH_CAVEATS) → PLAN (SHIPPABLE_WITH_CAVEATS) → IMPLEMENT (TDD, droplet) →
medição real. **Veredito D3 = GO (medido).**

**Dois achados Rule 9 que de-riscam todo o pg_scann** (memória `ah-batched-kernel-exists`): o kernel batched
AH-LUT (FastScan pshufb, `vec/ah.rs::ah_score_block`, a parte mais difícil) + o acesso às inverted lists
(`ivf.rs::list_entries`) **já existiam e estavam testados** — o glue novo é só `ann/ivf_aqah.rs` (índice IVF-AQ+AH:
empacota códigos no layout transposed block32 + scan 2-estágios probe→AH→rerank), provado correto (3 pg_tests
GREEN: recall-vs-exato, monotonicidade, negative-case).

**Medição (SIFT real, GT exato brute-force):** o IVF-AQ+AH entrega **~2.3× (recall 1.0) a ~7× (recall 0.95-0.99) o
QPS do full-precision IVF a recall casado** — captura ~5-7× dos ~25× do gap ScaNN (M33). Primeiro lever own-code
que MOVE o gap de verdade (M57 SBQ + M59-no-HNSW não moveram). Reabre honestamente o eixo de QPS que o M73 fechara
"pelos levers tentados".

**Caveat honesto (Regra 5):** medido a **n=5000 (subset SIFT), NÃO 1M** — o `AqQuantizer::train` naive é
**super-linear** (23s@5k), impraticável @ 1M in-session. A comparação RELATIVA (aqah vs f32, mesmo corpus, GT
exato) que o D3 pergunta É válida nessa escala; a medição full-1M exige otimizar o AVQ train (item concreto de
M77). O veredito GO é sobre **viabilidade algorítmica medida**, não promessa de vencer o ScaNN (isso é o M82 final).

**GATE ABERTO:** M76-M82 (o AM pgrx completo) arrancam. Release v0.67.0.
