# Milestone M70 — Remover pgvector totalmente

## Objective (from ROADMAP.md)

Religar as opclasses dos AMs próprios ao tipo próprio, migrar tabelas existentes, e remover pgvector +
pgvectorscale da distribuição — fechando "remover a dependência do pgvector totalmente".

## Definition of done — todos [x]

- [x] Opclasses/`::vector` resolvem ao `public.vector` own-code (drop-in) + `requires = ["vector_type"]`.
- [x] Migração documentada+testada (intermediário `real[]`; byte-cast direto corrigido honestamente).
- [x] `requires` pgvector/vectorscale zerado (flip); Dockerfile sem pgvector/pgvectorscale (pg_duckdb intocado).
- [x] Gate set-equal do AM GREEN sobre `public.vector`, sem pgvector.
- [x] pgvector+pgvectorscale ausentes; `CREATE EXTENSION theodb CASCADE` sem terceiros.

## Outcome

O TheoDB tornou-se o **1º AM permissivo com um tipo `vector` 100% own-code** — o pgvector e o pgvectorscale
foram REMOVIDOS totalmente da distribuição. O tipo `vector` (M69) migrou de `theodb.vector` para
`public.vector` (drop-in). A dependência circular foi resolvida via **flip**: `theodb_rs` virou a base da
stack (provê o tipo + os AMs ANN + os schemas theodb/ai); o umbrella `theodb` passou a requerer `theodb_rs`
(antes ambos requeriam o pgvector).

Validação (pg17 real, SEM pgvector): **229/230 suíte completa GREEN standalone** (a 1 falha é
`pg_cosine_simd_per_candidate_speedup`, teste de timing SIMD flaky sob carga — passa isolado; o M70 não tocou
`vec.rs`); os pg_tests do AM `set-equal-vs-seqscan` + 15/15 dtype + 13/13 HNSW GREEN sobre `public.vector`;
**`CREATE EXTENSION theodb CASCADE` sem pgvector** → extensões `theodb` + `theodb_rs` (zero vector/vectorscale),
`'[1,2,3]'::vector` resolve ao tipo próprio. Remoção total provada end-to-end.

Review (council-index-storage): greenfield SHIPPABLE; o BLOCKER B1 (playbook de migração impossível — citava
`theodb.vector` inexistente + colisão `public.vector`) foi corrigido honestamente (Regra 3): a migração de
instalações com pgvector usa um intermediário `real[]` (janela de manutenção), não o byte-cast falso; a
otimização byte-level ficou no backlog. Código ORIGINAL (VectorChord AGPL só estudo). Sem claim de
performance (o dado é o gate de não-regressão de recall). ADR-0029.
