# Milestone M54 — Vectorizer próprio (auto-embedding declarativo)
## Objective (from ROADMAP.md)
Embedding gerado/atualizado em INSERT/UPDATE declarativamente (como pgai vectorizer/Supabase/AlloyDB). Hoje: zero triggers em sql/; app mantém todo embedding. Revisita ADR 0007 (async permitido p/ o vectorizer; função embed continua síncrona).
## DoD (5 itens)
1. Discover blueprint: pgai vectorizer + Supabase (trigger→fila→worker); decisão de worker (bgworker pgrx vs cron/externo) por ADR revisitando 0007.
2. theodb.create_vectorizer(table, source_col, embedding_col, model): trigger AFTER INSERT/UPDATE enfileira (jobs c/ estados tipados pending/processing/done/failed + tentativas); worker consome em batch via embed_batch; retry bounded reusa http.rs.
3. Chunking helper SQL (recursive character split, tamanho/overlap configuráveis).
4. Crash-safety da fila: processing c/ owner morto → pending (visibility timeout); e2e stub determinístico (INSERT→embedding; UPDATE→re-embed; falha endpoint→retry bounded+failed tipado).
5. Métrica runtime (wiring): contador jobs processados/falhados consultável.
Risco ALTO: bgworker pgrx (FFI novo, lifecycle/sinais/shutdown); fila crash-safe (visibilidade). Mitigação: discover primeiro, estados tipados, worker nunca segura transação do usuário.
## Outcome
**RELEASED v0.45.0** (PR #55 merged → main 72bd199; tag; GitHub release). Os 5 itens do DoD cumpridos com evidência (13 pg_test + e2e end-to-end contra stub: INSERT→embedding; UPDATE→re-embed; falha→retry bounded→failed; métrica). 2 council reviews (rust-pgrx FFI + index-storage crash-safety) → READY_TO_MERGE após fixes HIGH (subtransação para catch-and-continue, reaper de órfãos, renovação de lease no fallback, owner uuid, target regclass, índice parcial). Deferidos honestos (v1 single-worker OK) rastreados no backlog: async-embed 3-fases, latest-wins por source_pk, multi-worker/multi-DB.
