# Milestone M4 — Operação básica (HA + backup)

## Objective (from ROADMAP.md)

Alta disponibilidade com failover automático (primary + standby) e backup contínuo + PITR. Aposta ADR 0002:
HA clássica Patroni/pgBackRest (battle-tested, OSS/on-prem), não o storage desagregado do AlloyDB.

## Definition of done (state at flip)

- [x] Primary+standby+failover automático sob RTO medido (Patroni) — `ha/failover-smoke.sh`: RTO≈19-23s (≤30),
  RPO=0 determinístico, + teste real de partição de rede (anti-split-brain: primary isolado vira read-only
  enquanto a maioria elege novo primary gravável).
- [x] Backup contínuo + PITR + backups agendados, com restore validado (pgBackRest) — `ha/pitr-smoke.sh`:
  stanza+check+backup full + WAL archiving contínuo + restore `--type=time` validado (keep presente, pós-alvo
  ausente) + caso negativo (alvo pré-backup recusado); cron agendado documentado no runbook.
- [x] Due-diligence de licença Patroni/pgBackRest permissiva — Patroni MIT + pgBackRest MIT (runbook § Licenças).

## Outcome

M4 entregue end-to-end e released em **v0.4.0** (PR #5, merge `223ee3c`, tag `v0.4.0`, GitHub release). CI verde
(4 jobs incl. **`ha-smoke`** que sobe o cluster Patroni e roda failover + PITR contra containers reais) fecha o
"testado em CI". Review READY_TO_MERGE — 1 BLOCKER (pitr flaky por colisão de segundo no alvo) + 1 HIGH (assert
de split-brain tautológico) + MEDIUMs corrigidos na raiz e re-verificados ao vivo (teste real de partição,
RPO=0 determinístico, negative-case PITR).

## Known gaps (honest, diferido p/ M5)

- `synchronous_mode` (zero-RPO sob carga); topologia 3+3 (janela sem replica pós-failover no 3+2);
  pg_hba/creds de produção (hoje dev-grade); DR cluster-level (restore para dentro do Patroni).
