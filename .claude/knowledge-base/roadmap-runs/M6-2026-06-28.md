# Milestone M6 — Analytics colunar / HTAP

## Objective (from ROADMAP.md)

Camada de armazenamento colunar (DuckDB-powered, pg_mooncake MIT) para analytics rápido sobre dados
transacionais vivos, com escolha de plano row vs colunar.

## Definition of done (from ROADMAP.md) — all met (honestly)

- [x] Armazenamento colunar (pg_mooncake) habilitado + query analítica medida vs row-store — columnstore mirror (`CALL mooncake.create_table`), agregado medido (row 10.9ms vs columnar 44.3ms, match=True, 100k linhas, sync-barrier).
- [x] Escolha de plano row vs colunar documentada — EXPLAIN: mirror = `Custom Scan (DuckDBScan)` vs row = `Seq Scan` (`docs/analytics/columnar-htap.md`).
- [x] Honestidade: lakehouse DuckDB+Iceberg, NÃO in-memory como o AlloyDB (D2) — docs + report.

## Outcome

M6 entregue measurement-first: a capacidade columnar/HTAP do pg_mooncake (MIT) foi **provada + medida** vs
row-store, com a escolha de plano row-vs-colunar capturada por EXPLAIN, e a honestidade D2 (lakehouse on disk,
não in-memory) documentada. Honesto (Regra 5): o ganho columnar NÃO aparece a 100k (row-store mais rápido); o
ganho em escala maior é UNBENCHMARKED — nenhum claim de speedup. Licenças MIT pinadas (pg_mooncake/pg_duckdb/
DuckDB). O build PG17 from-source (Rust+pgrx+DuckDB) foi tentado (`packaging/Dockerfile.columnar-pg17probe`) e
bloqueado num pin de rustc/MSRV no HEAD upstream — registrado honestamente; a adoção de pg_mooncake na imagem
shipped é o passo **gated** (a distribuição não embarca pg_mooncake ainda). Substrato de medição = distribuição
canônica MIT (PG18). Review READY_TO_MERGE (HIGH sync-barrier + MEDIUMs corrigidos e re-verificados ao vivo).
