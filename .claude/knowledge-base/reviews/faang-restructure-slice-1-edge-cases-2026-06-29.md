## MUST FIX

### EC-1: "byte-identical generated SQL" is the WRONG parity assertion — pgrx declares the order UNSTABLE
- **Affected task:** T2.1, Goal, Coverage Matrix #4, Global DoD, Integration Validation.
- **Kind:** NEGATIVE (a false-negative gate — would fail a correct refactor, or mask the real proof).
- **Family:** Format / verification oracle.
- **Scenario:** the M17-generated `theodb_rs--1.0.0.sql` header states verbatim: *"This file is auto generated by pgrx. The ordering of items is not stable, it is driven by a dependency graph."* Splitting `lib.rs` into modules can legitimately change the EMISSION ORDER of the same CREATE statements (the dependency graph is rebuilt). The plan asserts "byte-identical SQL" (T2.1 VERIFY `diff`, Goal, DoD) — a `diff` could then FAIL on pure reordering even though the surface is semantically identical, OR (worse) a reviewer trusts byte-diff as the parity oracle and misses that the REAL proof is behavioral.
- **Impact:** a correct, behavior-preserving refactor could be wrongly blocked by a byte-diff; the parity gate points at the wrong oracle.
- **Suggested fix (≤1 sentence):** change the schema-parity assertion from "byte-identical" to **"semantically identical — the same set of CREATE FUNCTION / extension objects (`theodb_rs._embed_text` + `theodb.embed`), compared order-insensitively (e.g., `grep -oE 'CREATE (FUNCTION|...)' | sort` equal)"**, and make the AUTHORITATIVE parity oracle the **18-test suite passing unchanged + the deployed `\df theodb.embed`/`\df theodb_rs._embed_text` surface** (behavior), not a text byte-diff.

### EC-2: moving `migrate-doc-check.sh` to `scripts/` breaks its `$HERE/docs/...` GUIDE path (Q1 resolved)
- **Affected task:** T1.1.
- **Kind:** NEGATIVE (a broken path → the doc-check fails or silently checks the wrong file).
- **Family:** Path / boundary.
- **Scenario:** verified `migrate-doc-check.sh:5-7`: `HERE="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"`, `GUIDE="$HERE/docs/migration/minimal-migration.md"`, `SMOKE="$HERE/migrate-smoke.sh"`. Today `$HERE` = repo root, so `$HERE/docs/...` resolves. After `git mv` to `scripts/`, `$HERE` = `…/scripts`, so `$HERE/docs/...` → `scripts/docs/...` (does NOT exist) → the guide check breaks. (`$HERE/migrate-smoke.sh` stays correct — the sibling moved too.)
- **Impact:** `bash scripts/migrate-doc-check.sh` fails (or, if it tolerated a missing file, would stop proving the guide↔smoke consistency) — a real CI gate breaks.
- **Suggested fix (≤1 sentence):** in T1.1, repoint ONLY the GUIDE line to `GUIDE="$HERE/../docs/migration/minimal-migration.md"` (leave `SMOKE="$HERE/migrate-smoke.sh"` — sibling); then PROVE with `bash scripts/migrate-doc-check.sh` exit 0.
