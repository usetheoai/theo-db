# Milestone M60 — Qualidade de recall do HNSW próprio

## Objective (from ROADMAP.md)

Fechar o gap de recall do `theodb_hnsw` vs pgvector a escala (500k×768d) — a fundação do pilar P0 (superioridade
vetorial medida) do Roadmap v5.

## Definition of done — reenquadrada (ADR-0030) e concluída

- [x] Discover linha-a-linha theodb↔pgvector (blueprint) — origem isolada; 5 levers refutados por medição.
- [x] Recall-PARIDADE com pgvector a 500k×768d (DoD reenquadrada, ADR-0030): SBQ 0.986 ≈ pgvector 0.988.
- [x] Re-comparativo SBQ vs f32 medido: SBQ 0.986 > f32 0.974.

## Outcome

CYCLE completo (discover deep-research → implement 2 fixes → benchmark medido em 2 droplets → review → release+merge).
**Achado decisivo (Regra 3):** o gate `recall@10 ≥0.99` é **artefato do dado** — o próprio pgvector só chega a 0.988
no corpus gaussian-mixture 256-cluster×768d (teto de recall@10 < 0.99 para índices HNSW). A DoD foi reenquadrada por
medição para **paridade-pgvector** (ADR-0030, alinhado ao North Star measurement-first ADR-0002), e a paridade de
recall foi **fechada pelo caminho SBQ** (0.986 ≈ 0.988, GT exato).

Duas correções algorítmicas reais (descida de build por beam ef=1; multi-entry `ep←W` — Malkov-Yashunin Alg.1 /
pgvector) foram implementadas e **REFUTADAS por medição** a 500k×768d (no-op no recall) — revertidas. Total de 5
levers de recall refutados (efc↑, MERGE, m↑, beam-descida, multi-entry). O gap do f32 puro (~1.4pt) permanece como
**follow-up autorizado (opção B)**. Bônus medido: o grafo multi-entry rende **+29% de QPS** a recall igual — achado
registrado para o M71.

**Release:** v0.61.0 (PR #71, merge→main, tag). **Sem claim de superioridade** — é paridade de recall; a
latência/QPS é escopo do M71.
