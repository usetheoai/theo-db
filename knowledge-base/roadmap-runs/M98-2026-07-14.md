# Milestone M98 — pgrx-upgrade + DataFusion/Arrow coexistence spike (the GATE)

## Objective (from ROADMAP.md)

Prove the single-planner columnar+AI pillar is technically feasible: upgrade pgrx to a version that
tolerates Apache DataFusion + Arrow in the same cdylib, and demonstrate DataFusion executes inside a
PG backend without an arrow ABI/version conflict. Go/no-go GATE for M99-M103.

## Outcome — GATE PASSED

pgrx 0.16.1→0.19.0 (edition 2024, One-Compile model, `public.vector` SqlTranslatable migrated to the const
API with `TypeOrigin::External` so the SQL name stays `vector` — no REINDEX, no user-SQL change). Apache
DataFusion 54 + Arrow 58 linked with `cargo tree`/`Cargo.lock` showing a SINGLE arrow major (v58) — the
coexistence proof, reproducible from the committed lock. **279 tests GREEN** (277 existing byte-identical +
2 new coexistence smokes: `theodb_df_probe()`=3 running a DataFusion aggregate over an Arrow batch inside a
PG backend under the `HeldInterrupts` query-cancel discipline). council-rust-pgrx review B1/H1/H2 fixed →
READY_TO_MERGE. Released as v0.85.0 (PR #97 merged to main). The honest-negative fallback (ADR D3) was not
needed. M99-M103 unblocked.
