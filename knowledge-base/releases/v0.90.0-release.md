## What shipped

M102 — AI predicates as SET-oriented, planner-optimizable operators:
- `ai.if_batch(condition, vals[])` — N rows → 1 inference round-trip (yes/no-shaped batched call, boolean framing matching per-row `ai.if`).
- `ai.if_costly(condition, val)` — declared with a high `COST` so `order_qual_clauses` runs cheap relational quals first: LOTUS dependency-safe filter push-down, delegated to the planner (Rule 9).
- `ai.call_count()` / `ai.call_reset()` — the wiring-triad runtime metric (inference round-trips).
- hermetic `theodb.llm_test_model = 'parity'` — proves batched == per-row without a live LLM (ADR D3).
- ADR-0043 revisits ADR-0007 (batched inference deferred half, closed for predicates).

## Measured evidence

- 307 pg_tests GREEN (+4 M102), zero regression.
- Deterministic: batched **1 round-trip** vs per-row **1000** (N=1000); push-down `id<=100` → **100 AI calls**, not 1000.
- Real OpenAI `gpt-4o-mini` (K=16, 3 runs): batched ≈1.0–1.3 s / 1 round-trip vs per-row 12.3–15.5 s / 16 round-trips = **≈12× lower latency** (runs: 12.32×, 11.81×).
- Sign-off: council-ai-in-db + council-security both READY_TO_MERGE (2 HIGH from council-ai-in-db — boolean shaping + ADR honesty — fixed in 4258058 and re-verified).

## Honest ceiling

A composability / round-trip win with STATISTICAL accuracy — **orthogonal to vector recall**, never framed as
"faster at vectors". The 3-axis cost is a fixed high constant (qual-ordering push-down, not a learned model); a
semantic-filter CustomScan node + a LOTUS proxy/oracle cascade with a recall guarantee are documented follow-ups.
