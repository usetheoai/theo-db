## What shipped

Durability crash-recovery **proofs** for issues #46/#47. The M48 fixes already existed in code but were `[NEEDS-REPRO]`
— never proven under a real crash (ADR-0014 flagged the proof as pending). This closes that gap:

- **#47 (`theodb_rs/isolation/crash_fold.sh`):** drives the M48 crash-injection GUCs (`theodb.test_crash_after_pages`
  / `theodb.test_crash_phase` → `std::process::abort()`) at all 3 VACUUM-fold phases (before-pivot / post-pivot /
  mid-reclaim) + WAL replay. Non-vacuous guard: ≥3 SIGABRT crashes + exactly +1 per phase. MEASURED: crash before
  the meta-pivot ⇒ old generation correct; crash after ⇒ fail-loud REINDEX; **never silently wrong** (the #47 worst
  case). Closes the ADR-0014 "Prova pendente".
- **#46 (`theodb_rs/isolation/crash_unlogged.sh`):** standby-promotion RED/GREEN toggle proving `wal_log_init_fork`
  (INIT-fork WAL-logging) is load-bearing — without it the promoted UNLOGGED index breaks (`aminsert before build`);
  with it, INSERT + scan work.
- `make -C theodb_rs/isolation check-crash`.
- Forward-compat `#[unsafe(no_mangle)]` for rustc ≥ 1.85 (edition 2024).

## Measured evidence

- 3 real SIGABRT crashes across all fold phases (confirmed in the Postgres log). 312 pg_tests GREEN, 0 regression.
- Issues #46 and #47 verified with measured evidence and closed. council-index-storage READY_TO_MERGE (2 non-blocking
  hardenings F1/F2 applied inline).
