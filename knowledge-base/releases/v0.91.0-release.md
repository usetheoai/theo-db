## What shipped

M103 — the summit (rung M-ε): the IVF vector index (`part_id` + raw `vec` bytea) stored AS columns co-resident with
the scalar `label` + analytical columns in a `theodb_columnar` table, so a scalar-prefiltered vector top-k + an
analytical aggregation compose in ONE column-pruned scan (own code; Lance is a file-format design study only, D1).
- `theodb.vindex_assign` — the real IVF partition per row, materialized as a column.
- `theodb.vindex_knn_columnar` — filtered top-k reading ONLY the 4 index columns (column pruning).
- `theodb.vindex_decode_bytes` — the isolated decode-cost control (benchmark).
- `theodb.f32vec_to_bytea` — encode a vector into the raw-vector column.
- ADR-0044.

## Measured evidence

- 312 pg_tests GREEN (+5 M103), zero regression.
- **GATE (recall correctness):** the co-resident filtered top-k is BYTE-IDENTICAL to the exact filtered brute-force
  (`m103_full_probe_byte_identical_to_exact_filtered`) — sharing the M90-M95 `Scored` tie-break + `vec::l2_dist_from_bytes`.
- **Column pruning (isolated control):** decode of the 4 index columns (49.57 ms ± 0.29) vs ALL columns (219.81 ms ±
  1.78) on the wide index = **77.4 % of decode time saved**; composed filter-knn + aggregation in one plan (225.41 ms).
- Sign-off: council-vector-ann + council-index-storage + council-benchmark all READY_TO_MERGE.
